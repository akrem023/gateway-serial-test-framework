Method 3: Using the --add-test Agent (Guided, No Manual Editing)

Instead of hand-editing tests.py, run the interactive agent. It asks the
same three questions a developer answers when writing a TestCase, TestSuite,
and TEST_SUITES registration by hand — then generates that exact code and
appends it to custom_tests.py (tests.py is never touched).

    python3 main.py --add-test

Full example session:

The new test is immediately usable, same as any built-in suite:

    python3 main.py --list-tests      # shows get_wan_modelist
    python3 main.py --run get_wan_modelist

Notes on the prompts:
  - Pressing Enter on any field uses the default shown in [brackets].
  - Test names are auto-normalized to snake_case (spaces/dashes -> underscores,
    invalid characters stripped).
  - "Expected output substring" and "Custom validator" are mutually exclusive:
    if you provide a validator expression, it is used and expected_output is
    dropped, even if you typed something there first. The expression becomes
    a lambda, e.g. validate_func=lambda o: 'DHCP' in o and 'PPPoE' in o.
  - If the registration key you choose already exists (checked against both
    tests.py and custom_tests.py), the agent warns you and asks for a
    different key, or the word 'overwrite' to confirm replacing it. It never
    overwrites silently.
  - custom_tests.py is created automatically on first use and is re-checked
    with `python3 -m py_compile custom_tests.py` after every append.

Method 4: Web Dashboard (Browser UI)

A local web dashboard is also available, wrapping the same tested logic
behind a browser interface instead of a terminal Q&A. It supports both
AI-assisted extraction and manual field entry, with a live code preview
before saving - same safety net (duplicate-key protection, compile check)
as the CLI flows above.

Setup (first time only):
    pip install -r requirements.txt

Run:
    python3 app.py

Then open http://127.0.0.1:5000 in a browser. Stop the server with CTRL+C.

The dashboard has three pages, linked via the top nav bar:
  - Dashboard (/) - browse all registered suites (built-in and custom),
    color-coded by category, searchable. Click any test name to get an
    AI-generated plain-English explanation of what it checks and why.
  - Add Test - AI (/add/ai) - describe the test in plain English, click
    "Extract Fields", review/edit the AI-filled fields, then "Build Preview"
    and "Confirm & Save"
  - Add Test - Manual (/add/manual) - fill in the same fields directly,
    no AI call

Every save shows a toast notification confirming success or explaining
what went wrong (e.g. a duplicate key).

This does not replace --add-test or --add-test-ai - all three are separate
front-ends over the exact same generate_code()/append_to_file() functions
in add_test_agent.py.

⚠️ TROUBLESHOOTING
⚠️ Common Issues & Solutions
| Issue                          | Solution                                                                                |
| ------------------------------ | --------------------------------------------------------------------------------------- |
| **Connection failed**          | Check port: `ls /dev/ttyUSB*`<br>Check permissions: `sudo chmod 666 /dev/ttyUSB0`       |
| **Login fails after reboot**   | Use `--no-login` and login manually<br>Verify credentials in `config.py`                |
| **Test stuck at login prompt** | Script waits for `"LIVEBOX login:"` prompt<br>May need to press **Enter** manually      |
| **Timeout errors**             | Use `--config debug` for longer timeouts<br>Increase timeouts in `config.py`            |
| **Serial buffer issues**       | Add `time.sleep()` between commands<br>Use `connector.read_available()` to clear buffer |
